# I/I general posting setup validation — 1.0.0.88

The supplied 1.0.0.87 preview stack reaches Sales-Post.CheckBlockedPostingGroups and reports IMPRESS_INV/ITEMS. Invoice preparation already resolves IMP001..IMP999 from each nonzero invoice line's staged revenue and COGS requirements. Other retained order lines, and existing lines matched to zero-quantity invoice rows, retain their prior product posting group. Local standard BC source shows CheckSalesLines tests every buffered line and CheckBlockedPostingGroups does not require a nonzero Qty. to Ship or Qty. to Invoice. Therefore ITEMS can stop preview without being the posting profile of an active invoice line. The exact failing line was not included in the supplied error and was not inspected live.

After preparing all invoice lines, Codeunit 80029 now calls the resolver's PrepareInvoiceGeneralSetups. For lines with a type that requires mandatory fields, it rejects any non-IMP001..IMP999 group when Qty. to Ship or Qty. to Invoice is nonzero. It unblocks existing General Posting Setup combinations referenced by those order lines, including inactive ITEMS lines. It does not replace inactive lines' accounts with an arbitrary invoice profile. Other orders' unreferenced setup combinations are not scanned or unblocked. General Posting Setup is shared company data, so a successfully committed unblock also applies to other documents using that same combination.

As explicitly requested, the shared general posting profile resolver now allows blocked exact or compatible IMP setups to be reused. Exact matches are unblocked under the existing locks. Compatible candidates are checked against the full requested account signature, then blank required accounts are filled and Blocked cleared. Conflicting candidates are not modified. Non-IMP profiles are still excluded from profile selection. This shared resolver behavior also applies to its inventory transaction callers. G/L Account blocking and VAT Posting Setup blocking are unchanged.

All changes occur inside the existing posting/preview transaction; preview and failed posting roll back setup changes. No live records have been changed by building this package.

Production 1.0.0.88 and test 1.0.0.14 packages compile against the local BC symbols. Regression cases cover blocked exact reuse, blocked compatible extension, conflict preservation, inactive ITEMS setup unblocking without changing its group/accounts, unrelated setup isolation, and rejection of an active ITEMS line. BC runtime tests have not run.

# Compatible general posting setup reuse — 1.0.0.86

The supplied General Posting Setup.xlsx has IMPRESS_INV/IMP001 with Inventory Adjustment 5099; IMP002 with Sales 4011 and COGS 5011; and IMP003 with Sales 4230. The first two account requirements are complementary and can share one setup. The different sales account requires a separate setup when 4011 is already populated.

Codeunit 80026 now prefers an exact existing IMP setup, then searches compatible setups under the same general business posting group. Every required account must either be blank or equal the requested account. The complete signature is checked before any update. Only blank required fields are populated; existing matching accounts and unspecified fields are preserved. Conflicting candidates are untouched. Blocked setups, non-IMP setups, and malformed IMP codes are excluded. New allocation happens only when neither an exact nor a compatible candidate exists. Validation, profile locking and transaction boundaries remain intact.

This applies to all callers of ResolveGeneralPostingSetup, including invoice and inventory transaction preparation. Customer and inventory posting-group resolvers retain their existing rules. Existing IMP001/IMP002 records are not merged or deleted, and existing document references are not reassigned. On the supplied current data an exact sales request still reuses IMP002; on a fresh adjustment-then-sales sequence, the sales request fills IMP001 rather than creating IMP002.

Regression tests cover complementary requirements, a mixture of blank/matching required accounts, conflict rejection without partial updates, exact-match priority, repeated resolution, and blocked candidates. Existing tests cover business-group scope, ownership, invalid accounts, conflicting signatures and sequence allocation. Production/test compilation is the local verification; BC runtime execution requires the isolated test company and has not been performed. No live setup was changed.
